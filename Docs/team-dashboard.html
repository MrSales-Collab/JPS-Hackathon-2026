Why we're building this

A real person, a real headache.

"There are too many phone calls to make, and patients get annoyed when their appointments keep changing." — Aryan's sister, who works the front desk at a clinic. She's our north star.

Receptionists juggle calls, hunt for open slots by hand, chase no-shows, and write reminders one by one. It's slow, stressful, and easy to get wrong. We're not diagnosing anyone — we're handing the front desk a smart assistant for the scheduling grind.

What we're building

One orchestrator, three specialists.

A receptionist enters a patient. The system reads the situation, suggests the best slots with reasons, books it, and drafts the reminder — each agent handing its work to the next.

AGENT 01 · runs first

Triage

Asks how the patient feels + their SMS/email preference, then flags urgency and recommends timing.

analyze → priority
AGENT 02 · core

Scheduling

Owns the calendar. Finds open slots that match the urgency, and can view, add, delete & search appointments.

calendar brain
AGENT 03 · last

Communication

Drafts the confirmation + day-of reminder in the patient's preferred channel, tone-matched to urgency.

draft → send (demo)
intake → triage → scheduling → communication · each output feeds the next

The toolkit

  • ReplitWhere we built it (with the Replit Agent scaffolding the first version). Optionally moving to local VS Code now that it works.
  • StreamlitTurns our Python into a clean web app — tables, buttons, callout boxes. No HTML needed.
  • Google Gemini (free)Powers the three agents (model: gemini-flash-latest). Key stored in Secrets / env var, server-side & safe.
  • call_ai() abstractionAll agents route through one function — swap providers (Gemini → Claude, etc.) by editing just that one spot.
  • In-memory calendarOur own appointment list in session_state — no Google Calendar rabbit hole. We explain every line.
  • Demo-mode fallbackIf the key is missing or rate-limited, agents return a sample response so the app never crashes mid-demo.
  • Simulated sendThe reminder is drafted & shown with a Send button. Real SMS/email = future roadmap.
How it's wired

Application architecture.

Everything runs inside one Streamlit app. The receptionist talks to the UI; the orchestrator runs the three agents in order; each agent reads and writes the shared in-memory calendar; Google Gemini is the brain behind each agent (via a single call_ai() function).

User Our code (UI + agents) Shared data External AI

Presentation

Streamlit renders forms, buttons, tables & callout boxes. app.py

Logic

The orchestrator calls each agent in order and passes outputs forward. orchestrator()

Data

One Python list holds all appointments while the app runs. st.session_state

Intelligence

Each agent sends a prompt to Gemini and parses the reply. google-genai SDK

Where we actually are

Build status & what shipped.

The app is feature-complete and running. Steps 1–7 are done; we're on Step 8 (video + Devpost write-up). Here's the honest snapshot, including things we added beyond the original plan.

✅ Done — the full build

  • SetupStreamlit app scaffolded with the Replit Agent, running live.
  • Intake formName, DOB, phone, doctor, reason, insurance. Submitting runs Triage.
  • Triage AgentLive Gemini call → urgency level + recommended timing. Verified it reacts correctly (chest pain = high, checkup = low).
  • Scheduling AgentSuggests open slots with reasons as clickable cards; clicking books it onto the calendar as Confirmed.
  • Communication AgentDrafts a personalized, tone-matched reminder you can edit before a (simulated) send.
  • OrchestratorPipeline bar at the top shows Intake → Triage → Scheduling → Communication lighting up as each runs.

⭐ Added beyond the original plan

  • Emergency tierA level above High. Life-threatening symptoms trigger a red "call 911 / go to ER" banner and pause scheduling. Framed as a safety prompt, NOT a diagnosis.
  • Urgency dashboardColor-coded High / Medium / Low patient cards at a glance (contrast fixed for light & dark mode).
  • Slot accumulation"Show more options" adds fresh slots to the list (de-duplicated) so patients can compare and go back.
  • Demo-mode fallbackNever crashes if the API key is missing or rate-limited — shows a labeled sample response instead.
  • Clinical themeTeal/blue palette, gradient header, pill tabs — looks like a real product, not a default Streamlit app.

  • Gemini over ClaudeFree tier was enough; routed through call_ai() so we can still swap to Claude in minutes if needed. Watch the ~10 req/min free limit during the demo — click at a normal pace.
  • Own calendar, not GoogleIn-memory list avoids an OAuth rabbit hole and keeps everything explainable.
  • Simulated sendReal SMS/email (Twilio/SendGrid) stays as roadmap, not a 2-day build.
  • Vibe-coding done rightThe Agent built fast, but we must be able to explain every line in the video — that's a scored rule.
